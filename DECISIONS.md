2. **(13:00) Default model `gemini-3.8-flash`, override with `GEMINI_MODEL`.** Google's models page (checked 25 Oct 2026) lists it as stable with PDF/image input and structured output. `gemini-2.0-flash`, used before, is listed as shut down. No `thinkingConfig` or temperature is set: the page says `minimal` thinking errors, and the git history shows earlier INVALID_ARGUMENT failures from extra config.
3. **(13:02) Delete the two duplicate engines (`utils/ruleEngine.ts`, `utils/rulesParser.ts`).** The UI ran on them instead of the tested evaluator; they ignored `minSymptoms`, skipped unit conversion and invented lab ranges. The tested evaluator in `src/evaluator` is now the only decision path.
4. **(13:02) Split `src/rules/loader.ts` into `validate.ts` (browser-safe) + `loader.ts` (`fs` loading).** Lets the browser validate `rules.json` with the same validator the tests use. `loader.ts` re-exports everything, so existing imports and tests are unchanged.
5. **(13:03) Browser validates rules in `dev` mode, and the gate status is shown, not hidden.** In `prod` mode the gate blocks every rule, because no rule has `lastVerified` and several sources lack year or link. Hiding the product would not help users; faking verification data would break the no-fabrication rule. The provenance drawer says "Verification gate: not yet passed" with the count of missing items.
6. **(13:04) Null template tokens are removed with their parentheses.** `({year})` disappears when the year is null, instead of printing "null" or "(guideline)".
7. **(13:04) TSH tier A wording is derived from the matched range in `rules.json`.** For example, "Outside the standard reference range: below 0.4 mIU/L (lower end)" or "…: at or above 4 mIU/L (upper end)". No new cutoff or clinical claim is introduced. It is done in the evaluator, so the label, message and provenance all agree.
8. **(13:05) Minimal wording edits in `rules.json` to remove the banned word "normal".** "can look normal" became "can look reassuring". "Normal hemoglobin does not rule out…" became "Hemoglobin inside the range does not rule out…" (two places). Meaning is unchanged; cutoffs, sources and structure are untouched.
9. **(13:05) No-flag message wording.** The existing test requires "within standard guideline limits". The message reads "…is within standard guideline limits used here, so there is no guideline flag", and the chip says "No guideline flag".
10. **(13:06) Missing lab range shows "not provided".** The old UI substituted made-up default ranges.
11. **(13:08) Urgent banner triggers on `chest_pain`, `breathlessness` or `dizziness`.** These are the only urgent-type triggers in `rules.json`. The banner is static text and does not depend on lab values. It is not shown for other symptoms.
12. **(13:08) `hair_loss` → `thinning_hair` alias for the overlap note only.** This is an engineering mapping, not a clinical one: the iron list says "Hair loss" and the thyroid list says "Thinning hair". It is never used for tiers or flags. The overlap note appears when a ticked symptom is in both the iron and thyroid symptom lists, whether or not both tests were entered. Its purpose is to prompt asking about both.
13. **(13:09) Sanity bounds apply in canonical units.** Ferritin ≤ 5000 ug/L, Hb ≤ 25 g/dL, TSH ≤ 500 mIU/L. 120 g/L hemoglobin is accepted (= 12 g/dL). They are labelled "input sanity check, not a clinical limit".
14. **(13:09) The lab range uses the same unit as the result.** One unit dropdown per test avoids a second conversion step; the help text says so.
15. **(13:10) Gate requires an answer to the pregnancy question.** "Yes or maybe" counts as pregnant, because pregnancy changes the applicable ranges. A missing age or missing answer shows a friendly not-covered panel, never a result.
16. **(13:10) Samples set age 30 / not pregnant.** The gate needs these values. Every sample is labelled "Sample data, illustrative". The old personas, which included a fake branded lab report with a named patient, were removed.
17. **(13:11) Upload rows need an explicit "Looks right" tick, and a unit, before use.** Confidence < 0.8 is highlighted. Unsupported tests are listed as "not covered". Values are copied into the form; nothing is evaluated until the user submits.
18. **(13:11) Extraction output is validated strictly.** Any extra key, wrong type or out-of-range confidence rejects the whole payload. A date in an unexpected format becomes null for the user to fill in. A response that may be manipulated is discarded rather than partially trusted.
19. **(13:12) Explainer input is only the evaluator's structured output.** Marker, value, unit, tier label, flag type, lab range, position and matched symptoms; never the report, age or free text. The server validates it strictly. The banned-phrase filter runs on the server and again in the browser. Any failure shows a deterministic template, labelled as such.
20. **(13:12) Banned-phrase list extends the brief.** It adds `normal`, `healthy`, `abnormal`, `disease`, `prescri` and `mcg` to `diagnos`, `you have`, `mg`, `dose`, `treat`, `cure` and `supplement`. Word boundaries are used so "image" does not trip `mg`.
21. **(13:13) Rate limit is in-memory per function instance.** 6 extractions and 12 explanations per IP per minute. It is best effort (resets on cold start); there is no database by design.
22. **(13:14) Errors are never logged in the API handlers.** SDK errors can echo request contents. Users see generic messages only.
23. **(13:15) `vercel.json` added.** It sets `maxDuration` 30 s for `api/*.ts` (the SDK call aborts at 20 s), plus an SPA rewrite for everything except `/api/`. Static files take precedence over rewrites on Vercel.
24. **(13:16) Native `<dialog>` for modals and the provenance drawer.** It gives Escape-to-close, a focus trap and an inert background with no dependency.
25. **(13:17) Caveats accordion is open by default.** It meets both "accordion" and "keep all caveats visible".
26. **(13:18) The multilingual toggle (F9) was not built.** Machine-translated health text with no reviewer is a safety risk, and the time went to tests and safety. The UI is English-only and `lang="en"`.
